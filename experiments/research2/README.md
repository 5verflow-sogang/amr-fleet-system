## v0 학습 환경 (`payload_nav/`)

명세서 4장(D7)의 2D 환경이다. 동역학은 이진의 제동 모델(#55)과 같은 식·기본값이다.

```bash
uv run --frozen --with pytest pytest tests                         # 환경 검사

uv run python scripts/evaluate.py raw/proposed_s0_2026* --scenarios mixed      # S1·S2를 popout_prob대로 섞은 분포
uv run python scripts/evaluate.py raw/r2_s3_* --eval-list 0                # 시드 3 실행을 목록 0으로 (짝짓기 확인용)
uv run python scripts/evaluate.py --rule mass_agnostic mass_aware --eval-list 100 --scenarios mixed   # 규칙 정책 (참고 기준선)
```

- 평가 시나리오 분포(`[env.scenario]`)는 학습한 실행도 `--config`(기본 `config/env_v0.toml`) 것을 쓴다. 학습 시나리오만 바꾼 후보(예: 돌발 장애물을 더 자주)도 기준선·DWA와 같은 시나리오로 짝지어 평가된다. 관측·보상·로봇 설정은 실행의 `config.json` 그대로다. 학습 시나리오가 다르면 실행할 때 알리고 `meta.json`의 `train_scenario_differs`에 남긴다.
- 학습 시나리오만 바꾼 후보는 `train_ppo.py --val-config config/env_v0.toml`로 학습한다. 검증(`eval/*` 체크포인트 선택, `eval_common/*`)도 기준선과 같은 시나리오로 재서, 효과가 학습 데이터 때문인지 체크포인트 고르는 시험지 때문인지 섞이지 않는다. 쓴 값은 `config.json`의 `args.val_config`·`val_scenario`에 남는다.
- **후보와 기준선은 따로 평가하고 따로 analyze한다.** `--tag`로 학습한 후보도 `variant`는 `proposed` 그대로라, 같은 평가나 같은 analyze 입력에 섞이면 같은 비교군·같은 시드로 합쳐진다. `episodes.csv`의 `tag` 열(`--tag` 값, 기준선·규칙·DWA는 빈칸)로 가를 수 있다(analyze 경고는 민지 #203 리뷰 후속). 기준선은 태그 없는 폴더만 잡는 glob(`raw/proposed_s0_2026*`, 폴더 이름 `<비교군>_s<시드>_<시각>`)을 쓰고, 후보(`raw/proposed_s0_<태그>_*`)는 평가 폴더(`--out-dir`)를 따로 만든다.
- **v1 결과를 다시 만들 때**: 평가 시나리오가 `--config`에서 오므로 `config/env_v0.toml`의 `[env.scenario]`가 v1 때와 같아야 같은 결과가 나온다. 바뀌었으면 v1 실행 폴더의 `config.toml`을 `--config`로 준다.

**환경 규칙**

- 돌발 장애물은 경로상 출현 지점(`trigger_x`)을 지날 때 나타난다. 시간이 아니라 위치 기준이라 모든 정책이 같은 곳에서 같은 장애물을 만난다
- 출현 지점은 25 kg으로 반응 지연(0.1 s) 뒤 초기 속도에서 급정지했을 때 멈추는 거리 이후에 둔다. 미리 속도를 줄이면 모든 학습 질량에서 피할 수 있다
- 통로가 좁으면 멈춰 선 장애물을 비켜 갈 수 없어 장애물 앞에서 서야 한다(`popout_blocked`)
- 벽에 닿아도 충돌로 끝난다. 시간 초과(30 s)는 남은 시간을 관측하므로 실패(terminated)로 끝내고 −10을 준다

**시드 규칙** ([실험 설계](experiment_design.md) 2절)

| 용도 | 시드 |
| --- | --- |
| PPO 신경망 초기화 | 학습 시드 k (`--seed`) |
| 학습 환경 | 1,000,000 + 100·k + i (i = 병렬 환경 번호). 학습 시드끼리 겹치지 않는다 |
| 검증 시나리오 (체크포인트 선택) | 10,000 + 에피소드 번호. 모든 학습 시드가 같은 목록 |
| 평가 시나리오 (목록 k) | 100,000 + 1,000·k + 에피소드 번호. 학습 시드 k는 목록 k를 푼다(`--eval-list`로 바꿀 수 있다). S1·S2는 같은 번호를 쓰므로 (`scenario`, `scenario_seed`)로 구분한다 |

- SB3 `make_vec_env(seed=s)`는 환경 i에 s + i를 준다. 학습 시드를 그대로 넘기면 시드 k와 k+1이 환경 7개(8개 중)를 공유해서 학습 환경 시드를 따로 둔다
- `PPO(seed=k)`도 모델을 만들면서 환경 시드를 k + i로 다시 덮어쓴다. 그래서 `payload_nav/training.py`의 `make_model()`이 모델을 만든 뒤 학습 환경 시드를 다시 건다. 테스트(`test_training_envs_differ_between_seeds`)가 실제 학습 환경으로 확인한다
- 평가 목록이 시드마다 다르다. 같은 시드 k의 R1·R2·제안은 같은 목록 k를 풀어 짝지어 비교하고, DWA는 `--eval-list k`로 목록 k를 풀어 시드 k와 짝짓는다
- `--scenarios S1`·`S2`는 돌발 장애물 유무만 강제하고 나머지 난수 흐름은 그대로다. 같은 시드에서 저절로 S1이 나왔던 시나리오는 S1로 강제해도 같다

## 규칙 정책 (참고 기준선)

명세서 4-2절의 "안전 순항 속도를 지키는 규칙 정책"이다(`payload_nav/rule_policy.py`). **정식 비교군(B1·B2·R1·R2·제안)이 아니다.** 환경이 "미리 속도를 줄이면 모든 학습 질량에서 피할 수 있게" 만들어졌는지 확인하고, RL 결과의 충돌률·도착 시간을 읽는 기준으로만 쓴다. 가설 판정(`analyze.py`)에는 들어가지 않고 `per_seed.csv`에만 나온다.

관측 벡터 대신 환경 내부 상태(로봇 위치·속도, 보이는 장애물)를 바로 읽는다. 장애물은 나타난 뒤에만 보이므로 출현 지점은 RL 정책처럼 모른다. 학습이 없어 결정적이다.

- **조향**: 통로 중심선을 따라간다. ω 행동 = clip((−2y − 2θ) / 1.5, −1, 1)
- **순항**: 안전 순항 속도 $v_{\text{cruise}}(m)$로 달린다. 가장 짧은 출현 간격(0.5 m)에 장애물이 나와도 반응 지연(0.1 s) 뒤 급정지로 서는 가장 빠른 속도다. 출현 지점 하한(`min_trigger_x`), "설 수 있었는지" 판정(`popout_stoppable`)과 같은 식이다

```math
v\,t_{\text{react}} + \frac{v^2}{2\,a_{\max}(m)} = g_{\min}
\quad\Rightarrow\quad
v_{\text{cruise}}(m) = a_{\max}(m)\left(\sqrt{t_{\text{react}}^2 + \frac{2\,g_{\min}}{a_{\max}(m)}} - t_{\text{react}}\right)
```

$g_{\min}$ = `popout_gap` 하한(0.5 m), $t_{\text{react}}$ = `reaction_s`(0.1 s), $a_{\max}(m)$ = `max_linear_accel`. 0 kg 1.25, 10 kg 1.10, 25 kg 0.95, 30 kg 0.91 m/s다.
- **장애물**: 진행선(로봇 폭 + 양쪽 0.1 m) 안에 장애물이 보이면 급정지한다(조향 0, 토크를 제동에만 쓴다). 멈춰 선 장애물이면 진행선에서 비킬 때까지 서서 기다렸다가 다시 간다. 옆으로 비켜 가지는 않는다.
- **목표**: 남은 거리 d에서 v ≤ √(2 · 0.5·a_max(m) · (d − 0.05))로 줄여 목표 바로 앞에서 선다.

| 변형 | `run`·`variant` | 순항·감속에 쓰는 질량 |
| --- | --- | --- |
| `mass_agnostic` | `rule_agnostic` | 질량을 모른다. 가장 무거운 학습 질량 25 kg(`guard_payload_kg`) 기준 |
| `mass_aware` | `rule_aware` | 관측 질량(`mass_obs_kg`). 정보 조건 exact면 실제 질량이고, unknown이면 25 kg 기준(= `mass_agnostic`) |

```bash
uv run python scripts/evaluate.py --rule mass_agnostic mass_aware --eval-list 100 --scenarios mixed
uv run python scripts/evaluate.py raw/r2_s0_* --rule mass_aware --eval-list 0     # RL 실행과 같은 CSV에 같이 평가
```

- 학습 시드가 없어 `--eval-list`가 필요하다. CSV 열은 RL 실행과 같고 `train_seed`는 빈칸이다. 환경 설정은 `--config`(기본 `config/env_v0.toml`)의 `[env]`다.
- `mass_agnostic`은 질량을 보지 않으므로 R1·R2처럼 exact로 한 번만 평가한다.

**튜닝 목록(100·101) 결과 (10/12)**: `--scenarios mixed`, 목록마다 질량별 200회(두 목록 합쳐 질량별 400회, 돌발 장애물 출현 253회). 최종 평가 목록(0~9)은 쓰지 않았다. 시간 초과·목표 지나침은 0건이다. 도착 시간은 성공 에피소드 평균이다.

| 질량 (kg) | `rule_agnostic` 성공 / 충돌 | 도착 시간 (s) | `rule_aware` 성공 / 충돌 | 도착 시간 (s) |
| --- | --- | --- | --- | --- |
| 0 | 100% / 0 | 17.69 | 100% / 0 | 13.75 |
| 2 | 100% / 0 | 17.68 | 100% / 0 | 14.12 |
| 10 | 100% / 0 | 17.64 | 100% / 0 | 15.44 |
| 25 | 100% / 0 | 17.55 | 100% / 0 | 17.55 |
| 15 (미학습) | 100% / 0 | 17.61 | 100% / 0 | 16.19 |
| 30 (미학습) | 99.8% / 1건 | 17.53 | 100% / 0 | 18.17 |

- 학습 질량에서는 두 변형 모두 100%다. 환경 설계(출현 지점 하한)대로 미리 속도를 줄이면 모두 피할 수 있다.
- 질량을 알면 0 kg 도착 시간이 25 kg 기준 순항보다 22% 짧다(13.75 s vs 17.69 s). 명세서의 13.8 s vs 17.4 s와 맞는다.
- `rule_agnostic` 30 kg 충돌 1건(목록 100)은 25 kg 기준 순항(0.95 m/s)이 30 kg의 안전 순항(0.91 m/s)보다 빨라서다. 간격이 0.5 m 가까이에서 나온 경우로, 출현 순간 이미 설 수 없었다(`못섬` 1, 충돌 속도 0.13 m/s). 25 kg보다 무거운 미학습 질량에서는 질량을 모르는 규칙도 안전을 보장하지 않는다.

## DWA 비교군 (B1·B2)

명세서 4-4절의 기존 방법 비교군이다(`payload_nav/dwa_policy.py`). **이진의 DWA C++ 원본(`src/navigation/amr_planning_core`, #41)을 수정 없이 그대로 부른다.** Python으로 옮겨 쓰지 않는다. 옮기면 원본과 달라진 부분(rolling window, 장애물 층, 도착 판정 등)이 결과에 섞이기 때문이다.

- 원본을 공유 라이브러리로 빌드해 ctypes로 부른다(`dwa_cpp/dwa_c_api.cpp`, 처음 쓸 때 g++/clang++로 `dwa_cpp/build/`에 빌드, git 제외). 판단(`DwaPlanner::computeVelocityCommand`, 목표 방향 회전)은 C++ 원본이 한다
- Python은 ROS 노드가 하던 일만 맡는다: Nav2 local costmap 래스터(로봇 중심 3 × 3 m, 0.05 m 셀, 통로 벽 + LiDAR가 찍는 장애물의 지금 위치 + Nav2 inflation), 추적 결과(환경 장애물의 위치·속도·반경, 나타난 뒤에만 보임), 전역 경로(통로 중심선 전체, 플러그인처럼 경로째 넘긴다). 파라미터는 `amr_bringup/config/nav2_params.yaml`의 DWA 블록 그대로다(`lookahead_distance` 0.5 m, #195의 허용 속도·목표 앞 감속·속도 비례 기준점 켬). 예외는 네 가지다: `xy_goal_tolerance`는 환경 도착 기준(0.2 m), 샘플 수는 논문 값 20 × 30(창고 스택은 계산량 때문에 10 × 15), 제자리 회전은 끔(창고 스택은 45°, #244), TTC 회피 모드도 끔(창고 스택은 켬, navigation.md 4-10절). 넷 다 `DwaParams`에 적어 C API로 넘기고 테스트로 고정한다
- 질량은 가속 한계 `acc_v`로만 들어간다
  - **B1** (`b1`): 빈 차 기준 a_max(0 kg) 고정
  - **B2** (`b2`): 관측 질량 기준 a_max(m_obs). 질량을 모르면 B1과 같다. 정보 조건(정확·±30%·모름)은 B2에만 의미가 있다

```bash
uv run --frozen --with pytest pytest tests/test_dwa_policy.py
```

## v0 튜닝 기록 (10/11)

첫 시험 학습(제안 방법, 시드 0, 100만 스텝)이 성공률 48%·충돌률 45%였다. 원인을 찾고 공통 설정을 고른 기록이다. 고른 설정은 세 비교군(R1·R2·제안)이 모두 쓴다. 질량 관련 설정 말고는 비교군 사이에 차이를 두지 않는다.

### 원인

- **덜 학습됨 + 학습 불안정**: 100만 스텝 끝까지 성공률이 오르는 중이었다. 정책 변화량(`approx_kl`)이 0.014 → 0.056으로 계속 커졌다(안정 범위 0.01~0.02).
- **너무 빨리 달려 못 섬**: 충돌은 전부 돌발 장애물이다. 업데이트 제한만 건 후보(B)를 질량별로 평가하면(질량마다 100회), 충돌 44~46건 중 35~46건이 "나타난 순간 이미 설 수 없던" 경우다. 10 kg 이상에서는 충돌이 전부 이 경우다. 충돌 속도는 1.3~1.6 m/s로, 안전 순항 속도(0 kg 약 1.25, 25 kg 약 0.95 m/s)보다 빠르다.

### 후보와 결과

- 공통: 제안 방법, 튜닝 시드 100·101(실험 설계의 예비 학습 범위 100~199), 검증 평가 25만 스텝마다 100회(검증 시드 `VAL_SEED_BASE` 10,000부터).
- 최종 평가 목록(시드 0~9)은 튜닝에 쓰지 않았다.
- 대표값은 **마지막 검증 평가 3회 평균**이다. 최고값은 여러 번 잰 것 중 최댓값이라 위로 치우치므로 참고로만 둔다. 검증 평가 100회라 한 번의 값은 ±10%p 정도 흔들린다.
- "기타"는 성공도 충돌도 아닌 종료(대부분 시간 초과, 일부 목표 지나침)다.

### 결론

- **업데이트 제한(`target_kl`)은 필수다.** 없으면 KL이 0.15~0.24까지 커지면서 좋아졌던 성능이 무너진다(A·C·D).
- **충돌 벌점을 키워야 "빨리 달려 못 서는" 문제가 풀린다.** 업데이트 제한만으로는 54%에서 멈춘다(B). −20은 부족하고(E) −40이 가장 좋다(F, 마지막 3회 평균 84%·충돌 5%).
- 채택: `r_collision = -40.0`, `[ppo] target_kl = 0.02`. 다른 값은 그대로다.

### 타당성 위협

- **설정을 제안 방법으로 골랐다.** 공통 설정(F)은 제안 방법의 검증 결과만 보고 골라 R1·R2보다 제안 방법에 유리할 수 있다. 예비 학습에서 R1·R2도 이 설정으로 안정적으로 학습되는지(KL, 성공률 추이) 확인하고 결과를 여기에 남긴다.
- **너무 조심하는 쪽으로 갈 수 있다.** 충돌 벌점(−40)이 시간 초과 벌점(−10)의 4배라, 부딪히느니 시간 초과를 고르는 정책이 될 수 있다. F(시드 100)는 실제로 학습이 길어질수록 기타 종료가 늘었다(201만 스텝 1% → 마지막 19%). 정식 평가에서 질량별 시간 초과율과 도착 시간을 같이 본다.

### 남은 확인

- 예비 학습: 비교군 3개(R1·R2·제안) × 시드 110~114. 실험 설계 2절의 "시드 5개 예비 학습으로 시드 수 결정"을 겸한다. 튜닝에 쓴 100·101과 겹치지 않게 110부터 쓴다.
- 이 결과로 (1) R1·R2가 F 설정에서 무너지지 않는지, (2) 질량별 시간 초과율과 도착 시간, (3) 본 실험 학습량(200만 또는 300만), (4) 시드 수(10 또는 20)를 정한다.
- 정식 평가(`evaluate.py`, 정보 조건 4개)로 "설 수 있었는데 충돌"이 줄었는지와 무거울수록 느리게 달리는지 본다.

## 학습 곡선 비교 (튜닝)

튜닝 후보는 마지막 값 하나가 아니라 **곡선 전체**로 비교한다. 마지막 값만 보면 빨리 배우는지, 중간에 무너지는지, 시드마다 흔들리는지가 사라진다.

- **비교군(R1·R2·제안)끼리는 `eval/*`로 비교하지 않는다.** `eval/*`는 비교군마다 학습 질량으로 재서, 10/15 예비 학습에서 0 kg만 잰 R1이 가장 좋아 보였다(성공 91.8%). 질량별 평가로는 R1이 R2보다 나빴다(성공 91.4 vs 95.0%, 30 kg 시간 초과 11.2%). 비교군 곡선은 `--panels common`(`eval_common/*`)으로 그린다. 같은 비교군의 튜닝 후보끼리는 `eval/*`로 비교해도 된다.

```bash
uv run python scripts/plot_curves.py --out raw/curves/<이름> \
    --group F raw/proposed_s100_<시각> raw/proposed_s101_<시각> \
    --group H raw/proposed_s100_<시각> raw/proposed_s101_<시각>
```

- **같은 구간에서 비교한다.** 실행마다 학습량이 다르면(예: 272만 스텝과 103만 스텝) "최종"이 서로 다른 구간의 평균이 되어 비교할 수 없다. 그래서 요약은 기본으로 **모든 실행에 공통으로 있는 마지막 스텝까지** 잘라서 내고, 그래프에 그 위치를 점선으로 표시한다. `--until <백만 스텝>`으로 정할 수 있고, `--until 0`이면 실행마다 전체를 쓴다.
- 평균 곡선(굵은 선)도 모든 시드가 있는 구간까지만 그린다.
- 튜닝 실행은 검증 점이 충분하도록 `--eval-every` 10만 이하로 둔다 (v0 튜닝은 25만이라 200만 스텝에 8점뿐이었다).

## v1 튜닝 기록 (10/12~10/15)

v0 설정(F)으로 학습한 제안 방법을 질량별로 평가하니 **무거워도 속도를 줄이지 않았다**(0 kg 1.02 m/s, 25 kg 0.99 m/s). 그래서 25 kg에서 충돌이 7.8%로 0 kg(1.4%)의 5배였다. 연구 질문(질량에 맞춰 달리는가)에 답하려면 질량에 따라 행동이 달라지는 정책이 학습되어야 해서, 보상을 다시 골랐다. 고른 보상은 세 비교군(R1·R2·제안)이 모두 쓴다.

### 원칙

- **보상에 질량을 넣지 않는다** (명세서 4장). 질량은 전이(무거우면 덜 선다)와 관측(제안 방법만)으로만 들어간다. 보상이 질량에 따라 달라지면 R2는 보지 못하는 값에 따라 벌을 받고, 비교군 차이가 관측 덕인지 보상 덕인지 나눌 수 없다.
- v0와 같이 튜닝 시드 100·101, 튜닝 평가 목록 100·101만 썼다. 최종 평가 목록(시드 0~9)은 쓰지 않았다.

### 결론

- **채택: G.** 보상 값은 `config/env_v0.toml`과 `payload_nav/env.py` 기본값에 반영했다.
- F는 질량에 따라 감속하지 않는다(기준 1 탈락). 충돌 벌점이 속도와 무관해 빠르게 부딪히는 것과 살짝 닿는 것이 같은 벌이라, 미리 감속할 이유가 약했던 것으로 본다.
- H는 무거울 때 지나치게 조심한다(30 kg 시간 초과 21%, 성공 74%). 충돌 벌점이 도착 보상의 2~8배인 F의 틀을 물려받아 "부딪히느니 늦는다" 쪽으로 간다. v0 "타당성 위협"의 "너무 조심하는 정책"이 실제로 나타났다.
- G-E는 충돌이 가장 낮지만(2.6%) 보상에 질량이 들어가 원칙에 어긋난다.
- 충돌 속도 벌점은 질량과 무관하고 모든 비교군에 같게 걸린다. 질량 없는 보상만으로도 질량에 맞춘 감속이 학습될 수 있다는 근거가 G다.

## 결과 분석 (가설 판정)

`scripts/evaluate.py`가 만든 `episodes.csv`들을 모아 시드별 요약과 H1~H3 판정표를 만든다. 판정 기준은 [명세서 4장](../../docs/project-spec.md)과 실험 설계 메모(#72)를 따른다.

```bash
uv run python scripts/analyze.py raw/eval/*.csv --out raw/eval/analysis
uv run --frozen --with pytest pytest tests/test_analyze.py
```

- 분석 단위는 시드다. 비교군 간 차이를 평가 목록 k(`eval_list`)끼리 짝지은 뒤 재표집하는 부트스트랩으로 95% CI를 낸다(하네스와 같은 방식). DWA는 `--eval-list k`로 푼 목록 k를 시드 k와 짝짓는다. 목록 번호 없이 한 번만 평가한 결과는 고정값으로 쓰되 경고한다(시드 간 흔들림이 CI에서 빠진다).
- 시나리오 짝짓기 키는 (`scenario`, `scenario_seed`)다. S1·S2가 같은 시드 번호를 쓴다.
- 충돌률 분모는 돌발 장애물이 나타난 에피소드 전체(`popout_appeared`)다. `popout_stoppable`은 분모에서 빼지 않고 충돌 원인을 나누는 데만 쓴다(설 수 있었는데 충돌 / 너무 빨라 못 섬). 도착 시간은 두 비교군이 모두 성공한 같은 시나리오끼리 비교한다.
- 결과: `hypotheses.md`(판정표), `hypotheses.json`, `per_seed.csv`(비교군·정보 조건·질량·시드별 충돌률·성공률·도착 시간)
