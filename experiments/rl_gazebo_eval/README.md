# 연구 2 RL Gazebo 평가 환경 확인 (3주차 작업 11)

연우 2D 학습 환경([research2](../research2/README.md))과 같은 시나리오를 Gazebo(`amr_gazebo` `rl_eval.launch.py`)에서 돌리고, **같은 정책**을 두 환경에 넣어 에피소드마다 결과를 비교했다. 학습한 PPO를 Gazebo에서 다시 잴 때 "2D와 Gazebo가 얼마나 같은 문제인가"를 먼저 보는 실험이다.

## 방법

- 시나리오: 평가 목록 0의 에피소드 0~9, S1(돌발 장애물)·S2(정밀 정지) 강제 (2D `evaluate.py`와 같은 규칙)
- 질량 0·10·25 kg. Gazebo는 질량마다 다시 띄운다 (URDF `payload_mass`, DiffDrive 가속 상한을 풀어 바퀴 토크 한계 3 N·m가 가감속을 정함)
- 정책 `brake` (`amr_gazebo/rl_policies.py`): 출발 속도로 중심선을 따라가다 목표 앞에서 토크 한계 감속으로 서고, 진행선 앞 장애물이 제동 거리 안이면 급정지. **비교군이 아니라 환경 확인용 시험 주행기**다
- 2D는 같은 함수를 `run_2d.py`로 2D 환경 상태에 붙여 돌리고 지표는 2D `evaluation.run_episode` 그대로다
- 총 Gazebo 60회, 2D 60회 (질량 3 × 에피소드 10 × S1·S2)

```bash
bash experiments/rl_gazebo_eval/run_gazebo.sh 10 brake      # Gazebo 60회 + 2D 60회 + 비교 (컨테이너, gymnasium 필요)
python3 experiments/rl_gazebo_eval/compare.py results_gazebo.csv results_2d.csv
```

- **S2(정밀 정지) 30회는 결과가 모두 같고 소요 시간 차이가 0.02 s 안이다.** 가속·감속·정지 판정이 2D와 같게 돈다
- S1에서 다른 3회는 모두 "2D는 섰는데 Gazebo는 부딪힘"이다. 셋 다 반응 지연 포함 급정지로 설 수 없는 경우(`popout_stoppable` False)라 경계에 있던 에피소드다
- 원인은 Gazebo가 조금 더 밀리는 것이다. 둘 다 섰던 에피소드의 제동 거리(나타난 순간 → 멈춤)가 Gazebo 쪽이 평균 +6~8 cm 길다 (0 kg 5쌍 0.742 vs 0.666 m, 10 kg 1쌍 0.979 vs 0.921 m). 명령이 브리지·DiffDrive를 거치는 지연과 바퀴 접촉 때문으로 보고, #55 이진 제동 실험의 Gazebo 고정 오차(약 2 cm)보다 크다
- 질량 효과는 두 환경에서 같은 방향이다: 같은 정책이 0 kg에서 S1 충돌 4/10, 25 kg에서 7/10 (2D 3/10, 7/10)
- 시험 주행기가 S1에서 자주 부딪히는 건 정상이다. 출발 속도를 줄이지 않으면 설 수 없는 시나리오가 대부분이다(설 수 있었던 S1: 0 kg 4/10, 10·25 kg 1/10). 미리 속도를 줄이는 게 학습할 일이다 (연구 2 가설)
- 원본: [results_gazebo.csv](results_gazebo.csv), [results_2d.csv](results_2d.csv). 열 이름은 2D `episodes.csv`와 같고 Gazebo 실측 열(`popout_gap_actual`, `start_speed_actual` 등)이 더 있다

### 고친 것

- 첫 실행에서 S1 결과가 60 %만 같았다. 비킨 장애물이 Gazebo 통로 벽에 막혀 통로 안에 남았기 때문이다 (2D는 장애물이 벽을 지나간다). 장애물과 벽의 충돌 비트마스크를 나눠 장애물이 벽을 지나가게 했다 (로봇은 둘 다와 부딪힘)

## 한계·다음

- 정책 관측은 2D처럼 GT다. 카메라·LiDAR로 장애물을 보는 것은 아니다
- 돌발 장애물은 트리거 1.5 m 앞에서 미리 제자리에 옮겨 둔다. 그 사이 LiDAR에는 보인다 (관측은 GT라 정책에는 안 보임)
- Gazebo는 실시간의 약 0.5배라 에피소드당 15 s 정도 걸린다 (2D는 수천 스텝/s). 평가 전용이다
- 학습한 PPO 연결: 정책 함수(obs dict → v, ω)로 감싸 `policy:=모듈:함수`로 넣는다. obs dict → 48차원 관측 변환은 연우와 같이 만든다 (`env._observe`와 같은 식)
