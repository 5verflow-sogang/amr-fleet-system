# 연구 1 중앙 관제 통신 장애 결과 (10/16~18)

가짜 로봇 5대(`fleet_fake`), 조건마다 10회(seed 1~10), 기종 `c2d-standard-8`. 실행 목록은 `runs.txt`(라벨 → Actions run id → GCS 경로 → git sha).
사전 예측 P1~P11과 판정은 `../predictions.md`(등록 커밋·시각 포함).

**논문**: KSC 2026 학부생 논문 「통신 불안정 환경에서 AMR 중앙 관제의 재시도 및 작업 회수 정책 분석」(10/19 제출). 아래 그림 세 장과 결과 표의 수치가 원고와 같다.

## 다시 만들기

```bash
cd experiments/research1/central
./fetch.sh                       # data/<라벨>/<반복>/ 에 지표 CSV만 받는다 (gcloud 로그인)
python3 analysis.py data         # 조건별 표, 기준 대비 짝지은 차이(부트스트랩 95% CI, Wilcoxon + Holm)
python3 compare.py data central_bo30_r3 hybrid_bo30_r3   # 두 조건 짝지은 비교
python3 figs.py data figures     # 논문 그림 1·2·3 (NanumGothic 글꼴 필요, matplotlib·numpy)
```

중복 실행(같은 작업을 둘 이상의 로봇이 수행)은 수행 로봇(`runners`)을 기록한 한 방향 조건 전부에서 0건이고, 양방향 단절(회수 5초)에서만 생긴다. `central_d0`·`d100`·`d200`·`d500`은 이 열이 생기기 전 코드로 돌려 중복을 셀 수 없다(재측정 `central_d0_v2`는 0건).

## 주의

- 장애는 서버 → 로봇 한 방향(양방향 단절 조건만 `relay_uplink`로 로봇 → 서버도 같은 일정으로 끊음), 앱 계층에서 메시지를 버린다(DDS RELIABLE 재전송 전 손실이 아님). 손실은 메시지마다 독립
- 가짜 로봇은 교통 통제(구역 허가)가 없다. ④ 자율 재할당(하이브리드)은 경매 메시지·모드 알림에 장애가 없어 상한
- 손실 30/50/70%의 식 일치는 사후 적합. 사전 예측 검증은 재전송 0·1번, 25초 작업, 재시도 간격 3초 등(P1~P11)
- 중복 실행이 있는 조건(양방향 단절)에서는 `runners` 마지막 값이 "끝낸 로봇"이 아니라 "마지막으로 시작한 로봇"이라 단절 로봇 완료 작업(a3_done)을 이 값으로 세면 틀린다. 로봇 상태 기록으로 추정한 실제 완료 작업은 완수 3.4건, 정지 4.1건(실행당)
- 단절 로봇의 작업 사이 대기 증가(P5)는 완료 → 다음 Ack 기준이다(`compare.py`의 `a3_wait`). `a3_gap`은 다음 BUSY까지로 정의가 다르다
- 재전송 횟수가 다른 조건끼리 Ack 왕복 P95를 비교하지 않는다 (실패한 명령은 기록에서 빠진다)
