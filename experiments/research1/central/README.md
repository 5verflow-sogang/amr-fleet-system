# 연구 1 중앙 관제 통신 장애 결과 (10/16~17)

가짜 로봇 5대(`fleet_fake`), 조건마다 10회(seed 1~10), 기종 `c2d-standard-8`. 실행 목록은 `runs.txt`(라벨 → Actions run id → GCS 경로 → git sha).
사전 예측은 `../predictions.md`(P1~P3, 10/17 17:12 등록), `../predictions_2.md`(P4·P5).

## 다시 만들기

```bash
cd experiments/research1/central
./fetch.sh                       # data/<라벨>/<반복>/ 에 지표 CSV만 받는다 (gcloud 로그인)
python3 analysis.py data         # 조건별 표, 기준 대비 짝지은 차이(부트스트랩 95% CI, Wilcoxon + Holm)
python3 compare.py data central_bo30_r3 hybrid_bo30_r3   # 두 조건 짝지은 비교
python3 figs.py data figures     # 그림 A·B·C (NanumGothic 글꼴 필요, matplotlib·numpy·scipy)
```

## 그림

| 파일 | 내용 |
| --- | --- |
| `figures/figA_conditions` | 조건별 평균 작업 완료 시간 변화(장애 없음 대비, 같은 seed 두 실행에서 **모두 끝난 작업끼리**의 평균 비율. 끝낸 작업 전체로 평균을 내면 장애 실행에서 늦은 작업이 빠져 손해를 작게 본다). 점선 = 급락 기준 +10%. 회색 = 95% CI가 0을 포함. 기준을 넘는 건 25초 작업 + 손실 70%(+18.8%)와 단절 30초 + 멈춤 정책(+21.7%)뿐 |
| `figures/figB_prediction(_wide)` | 예측 vs 실측. (a) 명령을 받기까지 추가 대기 W = r·p/(1−p) (b) 처리량 감소 (T+g0)/(T+g0+W). 검은 점 = 사후 적합(손실 30/50/70%), 흰 기호 = 사전 예측(재전송 0·1번, 25초 작업). 예측값이 같아 겹치는 점은 가로로 조금 띄웠다(보기용, 값 아님) |
| `figures/figC_policy(_wide)` | 단절 30초에서 끊긴 로봇의 정책(원고 3장 번호): ① 멈춤 ② 허가 지점 대기 ③ 받은 일 계속 ④ 새 일도 스스로(분산 경매, 상한). (a) 끊긴 로봇 완료 작업 (b) 전체 평균 완료 시간 변화. `data/`에 없는 정책은 빼고 그린다 |

`_wide`는 두 단 폭(180 mm), 나머지는 한 단 폭(88 mm)이다. 그림 B의 한 단 판은 (a) `figB_wait`, (b) `figB_throughput` 두 장으로 나눈다.

## 주의

- 장애는 서버 → 로봇 한 방향(양방향 단절 조건만 `relay_uplink`로 로봇 → 서버도 같은 일정으로 끊음), 앱 계층에서 메시지를 버린다(DDS RELIABLE 재전송 전 손실이 아님). 손실은 메시지마다 독립
- 가짜 로봇은 교통 통제(구역 허가)가 없다. 하이브리드는 작업 방송·모드 알림에 장애가 없어 상한
- 손실 30/50/70%의 식 일치는 사후 적합. 사전 예측 검증은 재전송 0·1번, 25초 작업, 멈춤 정책
- 중복 실행이 있는 조건(양방향 단절)에서는 `runners` 마지막 값이 "끝낸 로봇"이 아니라 "마지막으로 시작한 로봇"이라 단절 로봇 완료 작업(a3_done)을 이 값으로 세면 틀린다. 로봇 상태 기록으로 추정한 실제 완료 작업은 계속 3.4건, 멈춤 4.1건(실행당)
- 단절 로봇의 작업 사이 대기 증가(5.4)는 완료 → 다음 Ack 기준이다(`compare.py`의 `a3_wait`). `a3_gap`은 다음 BUSY까지로 정의가 다르다
- 재전송 횟수가 다른 조건끼리 Ack 왕복 P95를 비교하지 않는다 (실패한 명령은 기록에서 빠진다)
