# 휠 오도메트리 드리프트 실험 (D9)

- 담당: 지수
- 목적: 인계 계약(명세서 8-2절) "오도메트리: 드리프트" 기준값을 정한다 (D9, 민지 합의). 원 명세 "10m 사각형 복귀 오차 리포트"

## 방법 (UMBmark)

- 메인 통로 빈 곳에서 10 m × 10 m 사각형 한 바퀴(39.9 m)를 돌고 출발점으로 돌아온다
  - 출발 world (−5, 9). 반시계는 동쪽을 보고, 시계는 북쪽을 보고 출발해 같은 사각형 (x −5\~5, y 9\~19)을 돈다
  - 벽·랙·기둥과 1 m 넘게 떨어짐. 동적 장애물 없음, 카메라 끔
- 주행은 GT(`/amr_01/ground_truth/odom`)를 보며 정확히 돈다. 그래서 매번 경로가 같고 차이는 오도메트리 오차뿐이다 (복귀 GT 오차 1.8 cm)
  - 직선 0.5 m/s, 제자리 회전 0.5 rad/s
- 오차 = 출발 자세 기준 "휠 odom(`/amr_01/odom`)이 생각한 이동" − "실제 이동" (위치·방향)
- 반시계·시계 × seed 1\~10 = 20회 + 노이즈 끈 기준선 2회. 회마다 `wheel_odometry_node`를 새 seed로 다시 띄운다
- 두 방향을 도는 이유: 같은 seed의 방향 오차 합/2는 직진 중 쌓인 것(좌우 바퀴 반지름 차이), 차/2는 회전 중 쌓인 것(바퀴 간격 차이)이다

```bash
# 작업 컨테이너 안 (레포가 /ros2_ws/src에 마운트, experiments/는 복사해서)
bash experiments/odom_drift/run_drift.sh 10 /tmp/odom_drift/results.csv   # 약 45분 (sim 실시간 기준)
python3 experiments/odom_drift/analyze.py /tmp/odom_drift/results.csv
```

| 파일 | 내용 |
| --- | --- |
| `drift_square.py` | 사각형 한 바퀴 주행과 오차 기록 (CSV 한 줄) |
| `run_drift.sh` | sim 띄우고 방향 × seed 반복 |
| `analyze.py` | 분포, 보고 공분산 대비(NEES), 직진·회전 성분 |
| `results_d9_before.csv` | D9 전 설정 (계통 σ 0.5%, k 0.01), 10/8 |
| `results_b.csv` | **B안** (계통 σ 0.1%, k 0.005, #101), 10/9 |

## 결과

40 m 한 바퀴 뒤 휠 odom 오차 (노이즈 켬 20회)

| | D9 전 (σ 0.5%, k 0.01) | **B안 (σ 0.1%, k 0.005)** |
| --- | --- | --- |
| 노이즈 끔 (시뮬레이터 자체) | 19 cm (0.48%), 1.6° | 19 cm (0.48%), 1.6° |
| 중앙값 | 252 cm (6.3%), 19.9° | **114 cm (2.8%), 7.7°** |
| 평균 | 395 cm (9.9%), 35.0° | 143 cm (3.6%), 9.5° |
| 상위 10% (p90) | 615 cm (15.4%), 57.5° | **231 cm (5.8%), 16.7°** |
| 최대 (seed 3) | 1751 cm (43.9%), 155.7° | 570 cm (14.3%), 40.2° |
| 보고 1σ (위치 x·y / 방향) | 169·168 cm / 15.3° | 87·85 cm / 7.6° |
| NEES 위치 중앙값 / 평균 (기대 2) | 2.23 / 12.2 | **2.01** / 4.1 |
| NEES 방향 중앙값 / 평균 (기대 1) | 1.69 / 11.4 | **1.01** / 2.8 |
| 방향 오차 성분 중앙값: 직진 / 회전 | 28.3° / 6.5° | 6.4° / 4.4° |

- B안으로 중앙값 기준 위치 2.2배, 방향 2.6배 줄었다. 보정한 실제 AMR(이동 거리의 1\~2%)보다 조금 보수적이다
- **보고 공분산이 실제 오차와 맞는다**: NEES 중앙값이 기대값과 같다(2.01, 1.01). 평균이 기대보다 큰 건 좌우 바퀴 반지름 차이(계통 오차)가 공분산 모델에 없어서다. D9 전 12·11에서 4.1·2.8로 줄었다
- seed 3은 좌우 반지름 차이가 0.46%(3σ 넘는 경우)라 B안에서도 14%·40°다. 기준값은 중앙값·상위 10%로 정한다
- 노이즈를 꺼도 남는 0.48%·±1.6°는 반시계 +·시계 −로 대칭이라 회전량을 약 0.43% 크게 계산하는 시뮬레이터 자체 오차다 (실효 바퀴 간격이 모델 0.34 m보다 약 1.5 mm 넓은 효과). 작아서 보정하지 않는다

## D9 기준값 제안 (민지 합의)

10 m 사각형 한 바퀴(40 m) 복귀, seed 10개 × 두 방향, `/odom` 단독:

| 항목 | 기준 | B안 실측 |
| --- | --- | --- |
| 위치 오차 중앙값 | ≤ 3% (120 cm) | 2.8% (114 cm) |
| 위치 오차 상위 10% | ≤ 6% (240 cm) | 5.8% (231 cm) |
| 방향 오차 중앙값 | ≤ 8° | 7.7° |
| NEES 중앙값 (위치 / 방향) | 1\~4 / 0.5\~2 (공분산이 오차를 과신·과대평가하지 않음) | 2.01 / 1.01 |

- 실측에 약간의 여유만 둔 값이다. 엔코더 모델·오도메트리를 바꿨을 때 회귀 확인용으로 쓴다
- 위치추정 KPI(정지 3 cm 등)는 EKF·AMCL이 이 드리프트를 보정한 뒤의 값이다 (#104)
