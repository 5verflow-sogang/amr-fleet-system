## 3. 결과

조건마다 실행 10회의 값을 실행 단위로 묶었다. 신뢰구간은 하네스 요약(실행 단위 부트스트랩)이다.

| 지표 | 지연 0 ms | 지연 100 ms |
| --- | --- | --- |
| 완료 / 반복 | 10 / 10 | 10 / 10 |
| Fleet 메시지 지연 평균 | 0.36 ms (95% CI 0.35 ~ 0.38) | 100.85 ms (실행별 100.60 ~ 101.09) |
| 지연 P95 | 0.59 ms (0.57 ~ 0.62) | 101.22 ms |
| 지연 P99 | 0.76 ms (0.73 ~ 0.79) | 101.36 ms |
| 손실률 | 0 % | 0 % |
| Ack RTT 평균 (명령 448 / 444건) | 1.36 ms (1.32 ~ 1.40) | 101.74 ms |
| Ack RTT P95 / 최대 | 1.71 / 2.00 ms | 102.23 / 102.58 ms |
| Ack 비율 | 100 % | 100 % |
| 재전송 (명령당) | 0 | 0 |
| 실행당 할당 명령 | 44.8 (44.3 ~ 45.5) | 44.4 (44.0 ~ 44.8) |

- **주입 지연 정확도**: 100 ms를 주입하면 중계 1홉·타이머 주기만큼 약 0.5~1 ms가 더해진다. 지연 0 ms에서도 중계 자체가 0.36 ms를 쓴다.
- **Ack RTT ≈ 주입 지연 + 1.4 ms**: D8에 따라 서버 → 로봇 방향에만 지연을 걸어서, 할당 명령은 100 ms 늦게 가고 Ack는 바로 돌아온다.
- **재전송 0**: 재전송 간격 1초가 지연 100 ms보다 충분히 길어 불필요한 재전송이 없다. 손실을 주입하는 After 실험에서 재전송이 처음 나타날 것이다.
- **시작 직후 일시 지연**: 최대 지연이 지연 0 ms에서 140 ms, 100 ms에서 243 ms까지 한 번씩 튀었다. 둘 다 관측 시작 후 약 4초에, 같은 메시지가 로봇 5대 모두에 똑같이 늦었다. 장애 주입기가 기동 직후 잠깐 멈춘 것으로 보인다(새 구독자 연결 처리 등). 정상 구간 최대는 약 4 ms / 102 ms이고, 기준보다 10 ms 넘게 늦은 메시지는 약 19만 건 중 5건(0.003 %) / 15건(0.008 %)이다. 평균·P99에는 영향이 없다. After 실험에서 꼬리 지연을 볼 때는 시작 구간을 따로 확인한다.

## 4. 측정 방법 보정 (#127)

첫 GCP 실행에서 손실 0 %를 주입했는데 손실률이 0.8 %로 나왔다. `ros2 bag record -e`가 원본(`/fleet/*`)을 로봇별 중계본보다 먼저 구독해서, 녹화 시작 후 약 1초 동안 보낸 원본의 중계본이 녹화되지 않았기 때문이다.
주기 토픽(heartbeat, task_table)의 모든 로봇 중계본이 한 번씩 녹화된 시각 − 주입 지연을 관측 시작으로 두고, 그 전에 보낸 메시지는 판정하지 않는다([하네스 README](../../tools/harness/README.md) "관측 시작"). 이 리포트의 두 세트는 모두 이 규칙으로 쟀다.
